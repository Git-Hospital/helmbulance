# Helmbulance v0.1.0

The first release. Helmbulance installs a Helm chart into a throwaway kind cluster, runs day-two situations against the live release, and reports only what the cluster reproduced, with the evidence, the impact, a fix and the commands that reproduce it.

## Install

```sh
go install github.com/Git-Hospital/helmbulance/cmd/helmbulance@v0.1.0
```

It needs Go 1.27.2 (`go.mod`). A run also needs Docker, [kind](https://kind.sigs.k8s.io/), helm and kubectl on `PATH`; `test` and `matrix` stop with exit code 2 before any cluster when kind, helm or kubectl is missing, and `scan` needs helm only. CI tests with kind v0.33.0, Helm v4.3.0 and v3.22.0, and kubectl v1.37.1. `matrix` pins node images built for kind v0.33.

No prebuilt binaries in this release: `go install` or a build from the checkout (`go build -o bin/helmbulance ./cmd/helmbulance`).

## Scenarios

`helmbulance test <chart>` runs these, or the ones named with `--scenario`:

| Scenario | What it does | Finding IDs |
|---|---|---|
| `upgrade-without-values` | Upgrades with reused values (control), then with the values files only, and compares the Secrets the release renders, and which workloads restart. | HB-UV-001 Secrets change on every upgrade, even with the same values; HB-UV-002 Secret values lost or changed when an upgrade leaves out an install-time `--set`; HB-UV-003 an upgrade that changes nothing restarts pods |
| `chart-upgrade` | Installs an earlier chart version (`--from-version`) and upgrades to the chart under test with the same values. | HB-CU-001 the upgrade fails; HB-CU-002 the new version changes or drops Secret values; HB-CU-003 workloads are not healthy after the upgrade |
| `zero-downtime` | Sends a light, steady stream of requests to the release's Service while its pods are replaced, one workload at a time, and counts the failures. | HB-ZD-001 requests fail while the pods are replaced |
| `reinstall` | Uninstalls and installs again with the same values, and checks volumes and Secrets. | HB-RI-001 data survives but its credentials do not; HB-RI-002 a surviving volume comes back without its data; HB-RI-003 the release does not install again; HB-RI-004 a Secret that outlives the uninstall is replaced |
| `gitops-render` | Renders the chart without a cluster, as Argo CD does, and finds Secrets that would change on every sync. | HB-GR-001 |

Two more commands:

- `helmbulance scan <chart>`: a static pre-screen, no cluster, seconds. It lists **candidates** (HB-SCAN-001 to HB-SCAN-006) and the `test` run that confirms each. It exits 0 on candidates unless `--strict` is given, which exits 1.
- `helmbulance matrix <chart>`: installs the chart on Kubernetes 1.34 to 1.37, one kind cluster per version. HB-K8S-001 does not install, HB-K8S-002 not healthy, HB-K8S-003 deprecated or removed APIs, HB-K8S-004 other API server warnings.

## Reports

`test`, `matrix` and `scan` write `report.md`, `report.json` and `report.sarif` to `--report-dir` (default `helmbulance-report`). Exit codes: 0 nothing found, 1 a finding, 2 a usage or setup error, 3 a scenario could not finish (INCONCLUSIVE).

## How the verdicts are checked

`testdata/verdicts.yaml` holds the cases whose right answer is known: a fixture chart with one defect, and its fixed twin. CI runs every case under Helm 3 and Helm 4 and fails on a missed finding, a finding on a fixed twin, or a changed verdict. Finding IDs that no pair covers yet are listed there under `uncovered`, with the reason. The [known-bug corpus](../corpus.md) holds released versions of public charts with known defects, and their fixed versions; it is run again on the release commit (decision D8).

## Experimental

- **The GitHub Action.** It passes fewer options than the CLI, so it finds less: no install-only values, so no HB-UV-002, and no input yet for `--traffic-path`, `--traffic-target` or `--expected-rotation`. See [its limits](../github-action.md#status-experimental).

## Known limitations

Open issues that a v0.1.0 user can meet. Each one says what is still open:

- [#47](https://github.com/Git-Hospital/helmbulance/issues/47): helm and kubectl get no explicit context, so the `--cluster` check runs once, when the run starts.
- [#51](https://github.com/Git-Hospital/helmbulance/issues/51): HB-SCAN-003 reads the template source, so it misses some candidates and flags some guarded Secrets.
- [#53](https://github.com/Git-Hospital/helmbulance/issues/53): HB-RI-001 and HB-UV-002 judge a change from the key name, with the same Impact and Fix text for every key.
- [#56](https://github.com/Git-Hospital/helmbulance/issues/56): scan and matrix gaps (more immutable fields, checksum forms, kubeVersion constraints, field deprecations).
- [#57](https://github.com/Git-Hospital/helmbulance/issues/57): zero-downtime does not restart OnDelete StatefulSets.
- [#54](https://github.com/Git-Hospital/helmbulance/issues/54), [#55](https://github.com/Git-Hospital/helmbulance/issues/55), [#58](https://github.com/Git-Hospital/helmbulance/issues/58), [#59](https://github.com/Git-Hospital/helmbulance/issues/59), [#60](https://github.com/Git-Hospital/helmbulance/issues/60): smaller findings, docs, CLI robustness, wording and test gaps.
