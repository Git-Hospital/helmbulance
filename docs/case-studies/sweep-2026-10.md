# Sweep of ~1000 Artifact Hub charts (October 2026)

`helmbulance scan` on the most-starred charts on Artifact Hub, each compared with its previous version. A scan lists candidates; the ones below were then checked on a cluster.

| Result | Charts |
|---|---|
| clean | 753 |
| Secret values generated anew on every render (HB-SCAN-003) | 119 |
| checksum likely to change on the first upgrade (HB-SCAN-002) | 29 |
| immutable field changed since the previous version (HB-SCAN-001) | 17 |
| could not be pulled | 98 |
| total | 1005 |

## Immutable field changes outside major versions

| Chart | Versions | What changes | Status |
|---|---|---|---|
| yugabyte | 2026.1.1 → 2026.1.2 | StatefulSet selectors | confirmed, [reported](https://github.com/yugabyte/charts/issues/240) ([case study](yugabyte-2026.1.2.md)) |
| docker-registry-ui (Joxit) | 1.1.3 → 1.1.4 | Deployment selector contains `app.kubernetes.io/version`, so every `appVersion` change breaks the upgrade | confirmed; an open fix, [Joxit/helm-charts#22](https://github.com/Joxit/helm-charts/pull/22), was verified with Helmbulance and the results posted there |
| gaffer/hdfs | 2.2.0 → 2.2.1 | StatefulSet `volumeClaimTemplates` carry the chart version | static only |
| Sigstore rekor, fulcio; gluu; janssen | patch/minor | Job templates with fixed names | the Jobs have `ttlSecondsAfterFinished` (1 h for Sigstore): an upgrade fails only within that window; not reported |
| nacos, mssqlserver-2022, kubectl, clair | patch/minor | various | not checked |

## What it shows

- Most popular charts are clean. The common upgrade bugs cluster in a few patterns: version labels in selectors or volume templates, fixed-name Jobs, and checksums of templates with `lookup`.
- Two of the six charts checked on a cluster had a fix already proposed or the bug already known. Searching upstream first is part of the workflow: a verified comment on an existing PR helps the maintainers more than a duplicate PR.
